# 出图执行手册

> 提示词写对了只是拿到入场券。这一篇讲**怎么把 15 台跑出来、且长得像一套**。

---

## 1. 开跑前的四项设定

| 项 | 设定 | 理由 |
|---|---|---|
| 画幅 | 单机 **1:1**（方图），总图另行合成 | 方图才能按列等宽贴入，且不浪费画布 |
| 分辨率 | ≥ 1024×1024（有条件用 1536+） | 缩到列宽 480 后仍锐利 |
| 参考图 | 锚点图的成图 | 一致性靠它，不靠"再描述一遍" |
| seed | 固定并记录 | 不固定就只能靠运气复现 |

---

## 2. 锚点链：五步定调

1. **选锚点**：结构最经典、最容易判断对错的那一台（BOPET 选单螺杆挤出机）。
   选择标准：① 有明确的识别特征句；② 不剖切；③ 材质以白板为主。
2. **出 4 张候选**（同一提示词，只换 seed）。
3. **按 §4 的 5 条挑 1 张**，作为全系列风格锚。
4. **锁参**：记下这一张的 seed、采样器、步数、CFG，写进 `manifest.json`。
5. **派生其余**：以锚点图为参考图，权重 **0.4–0.6**，逐字复用 `[S1]`。

> 权重怎么选：0.4 更保各机自身结构；0.6 更保画风。**相似设备用 0.4，跨段差异大的用 0.5–0.6。**
> 切忌 0.7 以上——参考图的机器特征会被搬到别的机器上。

---

## 3. 提示词怎么喂

两个输入框，不要混：

```
正向框：[Subject 全文] + [S1 或 S2/S3/S4]        ← 风格块跟在正文后面，空一行也行
负向框：[N] + [extra_negative]                    ← extra_negative 放最后
```

- **不要**把负向词写进正向框再靠 `--no` 之类的语法，多数平台不认。
- **不要**在正向框里重复"等距/白底/光位"——重复权重会让模型过度响应风格，出图变"图鉴封面"。
- 参考图单独上传，不要写进文本。

`prompt-pack.json` 已经是拼好的 `positive` / `negative` 两栏，直接取字段即可。

---

## 4. 挑图：五条标准

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 视角等距正交，无三点透视 | 重跑；连续 3 次不过 → 检查风格块是否被改动 |
| 2 | 背景纯白，无渐变/地线/影棚布 | 负向补 `gradient background, studio backdrop` |
| 3 | 能指出识别特征句里那几个构件 | 改 Subject（补特征句 / 加位置词） |
| 4 | 画面零文字 | 负向第一位放 `text, letters, typos` |
| 5 | 比例正确（没被拉成另一台机器） | 补 `proportional character` 句；负向点名误认机型 |

**每台出 3–4 张挑 1 张。** 只出 1 张就选，等于把成本从"电费"转嫁到"返工"。

## 5. 批量与目录

建议目录（`<slug>` 由脚本生成）：

```
out/
├─ prompt-pack.md
├─ prompt-pack.json
├─ manifest.json
├─ raw/           D03_extruder_3d__s20261001.png  ← 候选，保留
├─ picked/        D03_single-screw-extruder_3d.png ← 采用，进排版
└─ line/          线稿同结构
```

批处理骨架（伪代码，换成你手上的生图接口）：

```js
const pack = JSON.parse(readFileSync('prompt-pack.json', 'utf8')).items;
for (const p of pack.slice(0, 1)) {                    // 先只跑锚点！
  for (const seed of [101, 202, 303, 404]) {
    await gen({ prompt: p.positive, negative: p.negative, seed, ref: null });
  }
}
```

**先跑锚点、人工挑定、再解锁其余**。脚本一次性跑完 30 条，会得到 30 张互不相干的图。

其它执行注意：

- 有速率限制的平台，`await` 串行 + 失败退避，不要并发打满。
- 中途鉴权过期（部分平台凭据约 15 分钟）会报 `AUTH_INVALID_TEMP_KEY` 之类，重新取一次即可，不要误以为提示词有问题。
- 原始候选**必须留**：挑图是主观的，一周后你要能回头换一张。

---

## 6. 一致性 QA：缩略图拼版

跑完 15 台后，**不要逐张看**。把 `picked/` 缩成 6×3 的联系表（contact sheet）： 

- 一眼能看出"哪张仰角不对、哪张背景偏灰、哪张比别人暗"；
- 这种对比比逐张检查有效 10 倍，因为人眼对"并排差异"极敏感。

差异票数 ≥3 张的，整批重跑那一段（通常是参考图权重不一致导致的）。

---

## 7. 登记与复现

`manifest.json` 每跑完一张就填：

| 字段 | 填什么 |
|---|---|
| `seed` | 该张实际 seed |
| `ref_image` / `ref_weight` | 参考图 ID 与权重；锚点图为 `null` |
| `model` | 模型名 + 版本 |
| `picked` | 采用的文件名（候选里挑中的那张） |
| `note` | 失败原因 / 手动修过什么 |

三个月后有人问"这张图怎么做的"，答案就在这张表里。

## 8. 时间与成本预期

| 环节 | 量级 |
|---|---|
| 建设备清单（15 台） | 1–2 小时（有文档时）；这是最值钱的两小时 |
| 写 15 条 Subject | 1.5–3 小时（每台 8–12 分钟） |
| 锚点图定调 | 4 张候选 + 挑图，10–20 分钟 |
| 批量出图 | 每台 3–4 张，视平台 20–60 分钟 |
| 挑图 + 登记 | 30 分钟 |
| 标注 + 总图合成 | 2–4 小时 |

**别把时间省在清单上。** 清单错一台，后面全是返工。

---

## 9. 出图能力不可用时

如果当前环境没有可用的生图通道，**不要伪造结果**。改为交付：

1. `prompt-pack.md`（可直接复制的提示词）；
2. 标注方案（中英名、字号、位置）；
3. 一句明确说明：`本包未执行出图，出图请在具备图像生成能力的环境中进行`。

用户拿这份包去任何生图工具都能跑，这本身就是可用交付。
